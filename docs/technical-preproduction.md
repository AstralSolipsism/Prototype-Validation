# 技术预生产验证总纲

## 目的

本仓库只回答会导致项目整体路线重做的高风险问题。DDD 中的限界上下文不是开发清单；技术预生产也不是缩小版正式游戏。

统一样板最终采用“河谷港镇—船舶”场景，但按停止线逐步物化：先手工空间与镜头，再移动参考系，再建筑编译，最后才让程序化生成器接管。

## 固定原则

1. 世界事实与视图表现分离。
2. 服务端维护唯一权威状态，客户端维护 Bevy 投影。
3. 六边形是索引与调度单位，不是自然地理边界。
4. 稳定领域 ID 不得替换为 Bevy `Entity`。
5. 参考系只允许平移与旋转，不允许缩放。
6. 生成器随机流按阶段、空间键和特征 ID 隔离。
7. 每个原型必须有明确失败条件，不能以“看起来差不多”通过。

## 顺序与停止线

### P0 基础契约

验证稳定 ID、世界时间、命令幂等、语义事件、确定性随机、刚性参考系、大坐标摄影机相对变换和回放顺序。

### P1 复杂路线卷轴摄影机

验证直线、轻弧、九十度转弯、十字路口、坡道、正反向行进和固定地标连续性。世界由手工盒体搭建，不引入程序化生成。

### P2 移动参考系与内外部统一

验证船体世界坐标、内部局部坐标、窗户真实开口、同一主摄影机、靠岸和上下船。

### P3 语义建筑编译器

验证同一蓝图派生房间图、门户图、碰撞、导航、近景网格、外壳、体块、HLOD 和剖视组。

### P4 确定性世界生成

验证 19 个六边形范围内的山脊、流域、河流、道路、港镇、建筑、路线和摄影机候选。

### P5 权威服务端、存档与回放

验证双客户端、命令幂等、版本检查、快照、增量日志、重连和恢复。

### P6 模拟分级与规模

验证百万冷身份、万级事件驱动人口、300 个高精度角色及 S0/S2 升降级。

### P7 多人兴趣域与区域权威

验证多分支预取、船舶移动区域、区域单写和显式移交。

### P8 垂直切片

验证住宅出发、取货、穿过路口、登船、航行、战斗、靠岸、交付、保存和重连的完整链路。

## 当前迭代范围

本迭代只交付 P0 和 P1 的第一版。明确不引入物理引擎、网络库、数据库、程序化地理、NPC 心理、LLM 或正式美术资产。
