# P7 多人兴趣域、区域单写与跨区权威人工验收清单

本轮不评价正式画面、网络压缩和 MMO 集群吞吐。目标是确认四个客户端、三个静态区域和一个移动船舶区域能够在同一权威世界中正确分发数据、迁移对象并保持单区单写。

## 运行证据

保留：

- `p7-machine-info.txt`
- `p7-data/p7-validation-report.json`
- `p7-data/p7-client-interests.json`
- `p7-data/p7-transfer-evidence.json`
- 完整控制台录屏或逐项异常记录

## 逐项检查

### 1. 四客户端与区域拓扑

必须显示：

```text
clients = 4
static_regions = 3
mobile_regions = 1
```

四个客户端应具有彼此独立的投影；船舶内部属于独立 MobileRegion。

### 2. 三类兴趣域分离

每个客户端必须分别显示：

- `visual_cells`
- `simulation_regions`
- `prefetch_cells`

`simulation_regions` 只包含当前权威区域；视觉和预取可以越过该区域，但不得自动获得远处实体的高精度权威状态。

### 3. 路口多出口预取

港口客户端应同时预取西、东、北三个候选出口，但仍只高精度模拟港口区域。东区人物不能因出口被预取而出现在港口客户端的 `detailed_entities` 中。

### 4. 船舱窗口兴趣

船上客户端通过窗口请求港口外部视觉对象时，其 `simulation_regions` 和人物权威归属仍必须是船舶 MobileRegion。

### 5. 船舶未来航迹预取

船舶客户端应预取东侧下一地区和后续航迹地区；预取不能触发船舱人物向静态区域迁移。

### 6. 远处人物摘要

远处重要人物应以 Cold/Warm 摘要存在于客户端投影中，但不应作为高精度实体泄漏到任何客户端。远处人物不能因无人靠近而被删除。

### 7. 单区单写和 epoch

四个区域均应显示一个 writer 和正整数 epoch。区域重平衡后 epoch 增加，旧 writer token 的写入必须被拒绝，新 writer 可以继续写入。

### 8. 静态区域跨区事务

人物 A 从西区迁入港口时，应经过 Prepare、DestinationAccepted、Commit、Ack。重复阶段调用不得重复创建人物或重复推进事实。

### 9. 故障恢复

程序会模拟：

- Commit 前目的地区出现意外副本；
- Commit 后源区残留意外副本。

恢复后每个对象必须只存在于一个区域，不能丢失或双份存在。

### 10. 登船和货物迁移

人物 B 和货物应通过显式事务从港口静态区域进入船舶 MobileRegion；两者的稳定身份和持久事实不变。

### 11. 船舶跨越静态地块

船从港口移动到东区时：

- 船舶 RegionId、writer 和 epoch 不变；
- 船舱人物 C 和货物仍由 MobileRegion 持有；
- 不应新增人物/货物跨区事务；
- 人物的当前世界地区可以随船更新，但权威区域不变。

### 12. 下船

人物 B 下船时必须发生 MobileRegion → 东区 StaticRegion 的显式迁移。人物 C 和货物仍留在船舶区域。

### 13. 分散区域并行

西区和东区无交互工作负载应至少使用两个并行 worker；并行结果和顺序执行结果、指纹必须完全相同。

### 14. 热点区域单写

四个客户端向同一港口区域提交 256 项操作时：

- `unique_writers = 1`
- revision 连续
- 所有客户端操作均被计入
- 不得为了显示“并行”而让多个线程同时写同一区域

### 15. 整体确定性

程序会独立运行完整场景两次。两次：

- 投影
- writer/epoch
- 迁移结果
- 并行结果
- 热点 revision
- 最终语义指纹

必须完全一致。

## 通过标准

所有控制台步骤均为 `[PASS]`，且：

```text
all_passed = true
fingerprints_match = true
```

三项 JSON 文件均存在且能够正常解析。

## 有条件通过

仅允许日志排版、控制台文字或采集脚本等不影响权威语义的问题。任何对象复制、对象丢失、兴趣泄漏、旧 writer 仍可写、船舱成员随静态区迁移或并行/顺序指纹不一致，均不得判为有条件通过。

## 失败

出现任一情况即失败：

- 客户端收到兴趣范围外的高精度实体；
- 预取等同于高精度激活；
- 同一 region/epoch 有多个 writer；
- 旧 writer 在重平衡后仍能修改区域；
- 跨区、登船或下船产生重复或丢失；
- 船跨地块时内部成员被迁入静态区域；
- 远处人物被删除；
- 分散区域并行与顺序结果不一致；
- 热点区域出现多个 writer；
- 两次完整运行指纹不同。
