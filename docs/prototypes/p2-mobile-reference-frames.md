# P2：移动参考系与内外部统一

## 启动依据

P1 人工 GPU 验收已确认：复杂三维路线、九十度转向、十字路口、坡道、双向行进和统一世界地标能够形成稳定卷轴画面。P2 不再重新证明 P1，而是验证大型载具作为移动区域时，内部和外部能否保持同一真实空间。

## 风险假设

服务端可以把船舶、空艇或移动堡垒作为独立移动区域，但客户端若不能同时满足以下条件，整个载具与开放世界路线将失效：

- 内部对象使用载具局部坐标；
- 载具在高精度世界坐标中连续移动；
- 窗外是真实世界，不是第二摄影机贴图；
- 船舱、船体、港口、岛屿和地标共享同一主摄影机与深度关系；
- 上下船只迁移参考系，不改变对象世界姿态；
- 客户端表现摇摆不污染服务端权威导航姿态；
- 千公里级坐标下厘米级局部关系仍然稳定。

## 当前实现范围

### 引擎无关核心

`mobile_region_core` 提供：

- `FrameBoundPose`：对象所属参考系及局部刚性姿态；
- `transfer_pose`：保持世界姿态的参考系迁移；
- `VehiclePoseState`：权威导航姿态与客户端表现偏移分离；
- `DockingLink`：静态区域与移动区域连接锚点；
- 移动内部对象的世界距离与一致性测试。

`world_math` 扩展：

- 运行时更新移动参考系姿态；
- 参考系之间的变换；
- 高精度 look-at 刚性变换；
- 大坐标下的摄影机相对转换。

### 无头验证

`p2_reference_frame_trace` 在约 9000 公里量级世界坐标上运行 3600 个采样，检查：

- 船舱内部固定点之间的距离误差；
- 世界参考系与船舶参考系双向迁移误差；
- 摄影机相对 `f32` 渲染坐标量化误差；
- 非有限值和传输次数；
- 表现摇摆与权威姿态分离。

### Bevy 视觉原型

`mobile_region_visual` 包含：

- 自由转向并绕岛航行的移动船舶；
- 甲板、船舱、家具和真实窗口开口；
- 固定岛屿、港口和高塔；
- 一台主摄影机；
- 舱内窗口与外部剖视两种镜头；
- 摄影机相对渲染；
- 红色主体在世界参考系和船舶参考系之间迁移；
- 可独立关闭的客户端表现摇摆。

## 自动通过条件

1. 新增 crate 和应用通过格式、编译及 Clippy；
2. 引擎无关测试通过；
3. P2 无头报告无非有限值；
4. 内部距离最大误差不超过 `1e-8 m`；
5. 参考系迁移平移误差不超过 `1e-8 m`；
6. 摄影机相对坐标量化误差不超过 `2e-4 m`；
7. 正反两次参考系迁移都被执行；
8. Windows 验证包成功生成。

## 人工 GPU 验收条件

详见 `docs/visual-acceptance/p2-checklist.md`，重点确认：

- 真实窗口视差；
- 船舱和外部的统一深度关系；
- 船体转向时外部地标连续；
- 船体与内部内容刚性一致；
- 上下船没有瞬移、重复或丢失；
- 大坐标下没有可感知抖动。

## 明确不在范围

- 正式海洋和空气动力学；
- 刚体碰撞与船体受力；
- 联网复制；
- 玩家造船；
- 完整建筑剖视与遮挡淡出；
- 船战、魔法和 NPC 生活；
- 最终材质、光照和美术。
