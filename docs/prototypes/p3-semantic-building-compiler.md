# P3：语义建筑编译器

## 启动依据

P2 已确认移动区域、统一内外空间、真实窗口视差、参考系迁移和大坐标摄影机相对渲染可行。P3 用于验证世界中的建筑应当以什么数据形式存在，以及同一份建筑事实能否同时支撑服务端空间规则、客户端完整三维表现、卷轴剖视、远景 LOD 和玩家增量修改。

## 风险假设

如果建筑的权威数据就是三角网格、独立模型实例或大量 Bevy 实体，则会出现：

- 服务端无法理解房间、入口、楼梯和用途；
- 玩家建造修改必须直接编辑渲染数据；
- 固定建筑和船舱需要两套系统；
- 近景、远景和剖视容易产生不同空间事实；
- 修改一扇门窗可能触发整栋建筑重建；
- 程序化聚落只能随机撒模型，无法保证功能合理。

P3 验证的核心路线是：

> 建筑蓝图和空间语义是权威数据；房间图、碰撞、导航、三维网格块、外壳、剖视分组和 HLOD 都是由同一蓝图确定性编译出的可删除派生数据。

## 已实现

### `building_core`

引擎无关建筑内核包含：

- `BuildingBlueprint`、楼层、房间、连续墙段、门窗、楼梯和屋顶区域；
- 稳定构件 ID 和建筑修订号；
- 房间重叠、墙体、门窗、楼梯、屋顶和主入口约束；
- 房间图和外部入口；
- 门窗门户图；
- 门洞分割后的墙体碰撞段；
- 房间导航面和交互门户；
- 按楼层、空间块和表现层组织的 `MeshChunkPlan`；
- `ExteriorShell`；
- 北、南、东、西和屋顶 `CutawayGroup`；
- 与近景结构同源的 `MassingProxy`；
- 与输入顺序无关的语义指纹；
- `BlueprintDelta`、`DirtySet` 和局部重编译影响计划。

### `p3_building_scenario`

确定性样板为一栋两层商住建筑，包含：

- 四个房间；
- 两个楼层；
- 真实外墙和室内分隔墙；
- 外部主入口；
- 室内通道；
- 多个窗户；
- 一部连接相邻楼层的楼梯；
- 同源屋顶和体块代理；
- 静态世界参考系与移动平台参考系两个实例绑定；
- 新增展示窗的局部增量修改；
- 删除楼梯后的不可达反例。

### `p3_building_trace`

无头报告检查：

- 同一蓝图重复编译的语义指纹一致；
- 不可达楼层被拒绝；
- 新增窗户后指纹改变；
- 新增窗户不改变建筑 Massing 包围范围；
- DirtySet 只影响一个墙段、一个楼层、相关房间、外壳、剖视和 HLOD；
- 窗户修改不无故重建导航、碰撞或 Massing；
- 同一建筑编译结果可以绑定静态与移动参考系；
- 房间图、门户、碰撞、导航、网格块和剖视分组均非空。

### `building_visual`

Bevy 可视原型同屏显示：

- 固定在世界参考系中的建筑；
- 同一蓝图绑定在移动平台上的建筑；
- 完整结构、外部壳体和 Massing 三种表现；
- 北、东、南、西、屋顶剖视和无剖视；
- 真实门窗开口、室内墙、楼板、楼梯和简化屋顶；
- 指定墙段新增或移除展示窗的局部重建。

## 人工 GPU 验收结果

项目所有者运行 P3 可视原型后确认总体通过，未报告阻塞性异常。人工记录见：

`docs/evidence/p3-manual-gpu-validation-2026-08-08.md`

人工验收确认以下路线可继续：

- 建筑四面、屋顶和室内能够作为完整三维对象呈现；
- 完整结构、外部壳体和 Massing 切换时保持同一锚点、尺度和主体轮廓；
- 剖视只改变表现可见性；
- 展示窗修改可以限制在指定墙段；
- 静态建筑和移动平台建筑可以复用同一编译结果。
