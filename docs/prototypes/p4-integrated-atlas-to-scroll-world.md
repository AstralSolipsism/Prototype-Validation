# P4 综合验证：从 Atlas 世界地图到可到达卷轴场景

## 一、验证方式

P4B～P4F 不再作为五轮彼此独立的技术原型和人工验收，而作为同一个端到端原型中的五个内部工作包。

最终只交付：

- 一份确定性的统一世界数据；
- 一个同时包含 Atlas 地图与局部三维世界的 Bevy 验证程序；
- 一套自动一致性报告；
- 一次完整人工 GPU 验收。

内部仍分阶段实现和自动测试，但任何工作包单独通过都不能使 P4 通过。只有完整链路成立才关闭 P4。

## 二、端到端链路

```text
WorldSeed + GeneratorVersion
        ↓
WorldAtlasManifest
六边形区域语义、地貌统计、特征骨架、边界契约、资源与历史初始条件
        ↓
RegionalMaterialization
高分辨率地形、山脊、谷地、河网、海岸、生态和可建设面
        ↓
HistorySimulation
迁徙、定居、产业、道路、港口、街区、扩张、冲突、灾害和遗迹
        ↓
BuiltWorldManifest
道路、桥梁、码头、街区、土地利用和 P3 建筑实例
        ↓
TraversalCompilation
可通行面、多模式通行图、建筑入口、路口和目的地
        ↓
ScrollViewCompilation
卷轴轨道、摄影机走廊、转向语法、剖视、遮挡和远景约束
        ↓
Atlas / Local 3D / LOD 统一表现
```

## 三、唯一验证样板

仍使用 19 个六边形的河谷—港湾世界，但不再把地块直接渲染成 19 个低采样平面。

完整样板至少包含：

- 独立 Atlas 世界地图；
- 分层设色、等高线、山脊线、谷线、流域、河流与海岸；
- 至少 7 个相邻地块的高分辨率详细物化；
- 山脉、山脚、山谷、河谷、低地、河口、港湾和海洋；
- 至少五个可追溯历史阶段；
- 老城区、新区、港口、农田、道路、桥梁、废墟和历史地标；
- 至少三条从详细世界中求解出的卷轴路线；
- 十字路口、弧线、坡道、建筑入口、码头和登船点；
- 同一个固定高塔或奇观在 Atlas、远景、近景和所有路线中保持唯一身份。

## 四、内部工作包

### WP-B：Atlas 语义地图

建立 `WorldAtlasManifest` 和 `AtlasCellSpec`，包含：

- 高程分布统计与等高线源数据；
- 山脊、谷线、河流、海岸和道路走廊骨架；
- 六边共享边界剖面和门户契约；
- 气候、生态、地质、土壤、资源、承载力和通行摘要；
- 人文历史引用和局部物化版本；
- 稳定对象 ID。

Atlas 视图必须是独立地图表现，不是把三维世界摄影机拉远。

### WP-C：详细自然地理物化

根据 Atlas 数据和边界契约，确定性生成：

- 高分辨率高度场或自适应地形；
- 山脊、支脉、谷地、盆地、河床和支流；
- 海岸、港湾、滩地和悬崖；
- 坡度、坡向、曲率、生态斑块、危险区和通行成本；
- 地形 LOD 与远景代理。

相邻地块可以独立加载和重建，但关闭调试线后不得看见接缝。

### WP-D：人文历史与土地利用

在自然地理上运行确定性的压缩历史：

- 迁徙与早期定居；
- 产业形成和人口扩张；
- 道路、桥梁、码头、城防和街区建设；
- 冲突、灾害、河流改道、衰退或政权变化；
- 当前土地利用、建筑任务书、遗迹和历史图层。

所有主要设施必须能够追溯到历史事件。

### WP-E：通行网络与卷轴视图编译

从详细世界事实生成：

- 步行、马车、车辆和船舶等多模式通行图；
- 道路、桥梁、建筑入口、院落、码头和登船点连接；
- 路线候选和分支；
- 坡度、曲率、宽度、净空和可达性验证；
- 卷轴轨道、观察侧、转向语法、剖视和摄影机走廊。

禁止直接连接地块中心充当最终轨道，禁止为了镜头移动世界对象。

### WP-F：跨尺度一致性

自动检查：

- Atlas 对象与局部对象使用同一稳定 ID；
- Atlas 边界契约与局部边界逐项一致；
- 局部数据重新汇总后符合 Atlas 高程、地貌、水系和土地利用摘要；
- 历史设施与局部对象一一对应；
- 地图目标、路线目标和实际到达对象 ID 相同；
- 建筑完整结构、外壳、Massing 和地图标记共享锚点；
- 删除客户端缓存并重新物化后结果一致。

## 五、统一验证程序

计划新增一个统一 Bevy 应用，例如：

```text
apps/p4_integrated_world_visual
```

它必须在一个进程中支持：

1. Atlas 地图模式；
2. 选择地块和查看完整语义；
3. 触发或查看详细地块物化；
4. 查看自然地理和历史调试图层；
5. 从地图选择港镇、高塔或其他目标；
6. 生成并进入真实卷轴路线；
7. 跨越多个地块到达所选目标；
8. 切换建筑完整结构、外壳和 Massing；
9. 返回 Atlas，验证对象和历史信息未变化。

不再分别提交五个互不相连的 EXE。

## 六、统一自动门禁

P4 最终 CI 必须同时验证：

- Atlas 清单确定性和序列化回读；
- 地块内部数据不退化为单一中心高程；
- 高分辨率地形与边界契约一致；
- 水系、海岸、道路和地貌约束；
- 人文历史因果与设施溯源；
- 通行网络和路线均落在真实可通行空间；
- 卷轴摄影机不改变世界事实；
- Atlas、局部场景、历史、路线和 LOD 的稳定 ID 对应；
- 清除派生缓存后重建结果一致；
- P0～P3 回归继续通过。

## 七、唯一人工 GPU 停止线

一次完整验收应执行：

```text
查看 Atlas 地图
→ 识别山脉、流域、河流、海岸、港镇和历史区域
→ 选择一个远景目标
→ 查看目标地块的地理与历史任务书
→ 进入详细三维世界
→ 沿真实生成的卷轴路线旅行
→ 跨越地块边界、路口、坡道、街区和建筑入口
→ 到达地图上选择的同一目标
→ 切换近景、外壳、Massing 和 Atlas 表现
→ 返回地图并核对同一对象与历史
```

人工通过标准：

- Atlas 与局部场景明显是两个尺度层；
- 地貌关系可由等高线、山脊、谷地、河流和海岸解释；
- 局部世界不再是着色倾斜平面；
- 当前聚落形态能够由自然条件和历史解释；
- 路线确实从现实道路和空间中生成；
- 远处看到的主要内容真实可到达；
- 地图、局部场景、卷轴路线和 LOD 不出现对象换位、复制或身份断裂。

## 八、停止线决定

- P4A 作为已通过的宏观骨架基础保留；
- WP-B～WP-F 只是实现与自动调试分组，不再分别进行项目所有者人工验收；
- P4 只有一次最终人工停止线；
- P5 在这次综合验收通过前继续阻塞。
