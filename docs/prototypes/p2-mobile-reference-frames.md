# P2：移动参考系与内外部统一

## 启动依据

P1 人工 GPU 验收已确认：复杂三维路线、九十度转向、十字路口、坡道、双向行进和统一世界地标能够形成稳定卷轴画面。P2 不再重新证明 P1，而是验证大型载具作为移动区域时，内部和外部能否保持同一真实空间。

## 风险假设

服务端可以把船舶、空艇或移动堡垒作为独立移动区域，但客户端若不能同时满足以下条件，整个载具与开放世界路线将失效：

- 内部对象使用载具局部坐标；
- 载具在高精度世界坐标中连续移动；
- 窗外是真实世界，不是第二摄影机贴图；
- 船舱、船体、港口、岛屿和地标共享同一主摄影机与深度关系；
- 上下船只迁移参考系，不改变对象世界姿态；
- 客户端表现摇摆不污染服务端权威导航姿态；
- 千公里级坐标下厘米级局部关系仍然稳定。

## 实现范围

### 引擎无关核心

`mobile_region_core` 提供：

- `FrameBoundPose`：对象所属参考系及局部刚性姿态；
- `transfer_pose`：保持世界姿态的参考系迁移；
- `VehiclePoseState`：权威导航姿态与客户端表现偏移分离；
- `DockingLink`：静态区域与移动区域连接锚点；
- 移动内部对象的世界距离与一致性测试。

`world_math` 扩展：

- 运行时更新移动参考系姿态；
- 参考系之间的变换；
- 高精度 look-at 刚性变换；
- 大坐标下的摄影机相对转换。

### 无头验证

`p2_reference_frame_trace` 在约 9000 公里量级世界坐标上运行 3600 个采样，检查：

- 船舱内部固定点之间的距离误差；
- 世界参考系与船舶参考系双向迁移误差；
- 摄影机相对 `f32` 渲染坐标量化误差；
- 非有限值和传输次数；
- 表现摇摆与权威姿态分离。

### Bevy 视觉原型

`mobile_region_visual` 包含：

- 自由转向并绕岛航行的移动船舶；
- 甲板、船舱、家具和真实窗口开口；
- 固定岛屿、港口和高塔；
- 一台主摄影机；
- 舱内窗口与外部剖视两种镜头；
- 摄影机相对渲染；
- 红色主体在世界参考系和船舶参考系之间迁移；
- 可独立关闭的客户端表现摇摆。

## 验收结果

项目所有者已完成实机人工验收，并确认所有需验证项均可行：

- 窗口是真实三维开口，船舱和外部共享同一透视与深度；
- 船舶转向时，外部地标视差连续；
- 船体、舱内结构、家具与主体刚性一致；
- 世界与船舶参考系迁移不产生瞬移、复制或丢失；
- 客户端表现摇摆与权威导航姿态可分离；
- 大坐标下未观察到影响使用的抖动或空间失真；
- 内部与外部能够作为同一连续三维世界被观察和交互。

人工记录：`docs/evidence/p2-manual-gpu-validation-2026-08-08.md`。

## 明确不在范围

- 正式海洋和空气动力学；
- 刚体碰撞与船体受力；
- 联网复制；
- 玩家造船；
- 完整建筑剖视与遮挡淡出；
- 船战、魔法和 NPC 生活；
- 最终材质、光照和美术。

这些内容属于后续工程或独立停止线，不推翻 P2 结论。

## 最终结论

**P2 通过。移动区域、统一内外空间和大坐标摄影机相对渲染路线成立，允许启动 P3 语义建筑编译器验证。**
